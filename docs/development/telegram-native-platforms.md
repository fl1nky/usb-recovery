# Локальные форматы Telegram

В разделе **Telegram** выбери папку с неподвижной копией данных через
**Источник…**, затем **Анализировать**. Для Desktop доступна кнопка
**Код Desktop…**: введи известный локальный код приложения либо явно отметь, что
в выбранном Desktop локального кода нет. Пустое незаполненное поле само по себе
не запускает попытку открытия без кода. Код используется один раз, передаётся
обработчику через stdin и не сохраняется в настройках, журнале или архиве.

| Платформа | Дополнительный локальный профиль | Что показывается |
|---|---|---|
| Android | `scheduled_messages_v2`, точные 8 столбцов и SQL-ключи, поддерживаемое TL-тело | Запланированные записи, отдельно от истории. Дата означает намеченное время отправки. Пустая запись о документе сохраняется, если исходный ID вложения присутствует, включая ноль. |
| iOS, прежний формат | SQLite-схема29: `messages_v29` и `service_v29` | Исходный текст, сохранённые ID и дата. Отсутствующий автор остаётся неизвестным. Вложения не декодируются. |
| iOS, Postbox | Читаемая SQLite Postbox25, таблицы t0/t4/t7 | Текст только при совпадении с индексом истории. ID сохраняются с пространством имён iOS. Неотправленные записи отмечаются отдельно; вложения и атрибуты не декодируются. |
| Desktop | Настоящие зашифрованные TDF-файлы локальных черновиков, теги FF03/FF05/FF06 | Неотправленный текст черновика, отдельно от переписки и удалённых сообщений. Автор, время создания и ID отправленного сообщения неизвестны. |

Desktop открывает прежнюю обёртку `key_datas`/`key_data0/1`, а также современную
обёртку KD2 версии2 с scrypt только с предоставленным известным кодом. Из двух
слотов выбирается единственное зафиксированное поколение; промежуточный или
устаревший слот не используется для повторной попытки. Неверный код не вызывает
попытку с пустым кодом. Явно указанное известное отсутствие кода открывает
сохранённую открытую обёртку, если она есть. Argon2id как выбранный KDF пока
не поддерживается. Для специальных локальных интеграций stdin также
принимает уже известный 256-байтовый локальный ключ. Подбора кодов, извлечения
ключей из памяти, входа в аккаунт и загрузки облачной переписки нет. Корневые
файлы авторизации Desktop, `maps` и настройки при обнаружении не открываются;
зашифрованная информация об аккаунтах внутри `key_data` остаётся непрочитанной.

Для KD2 сначала целиком проверяются трейлер, поколения, длины и параметры;
только затем выполняется одна операция KDF и проверка целостности шифрования.
Поддерживаются scrypt `N` от2 до131072 (степень2), `r` от1 до8 и `p=1`,
с пределом памяти192 МиБ; это включает параметры записи закреплённого Desktop
для x64 и Windows x86. Соль ограничена8–1024 байтами, трейлер4096 байтами.
Неизвестные версии и большие затраты отклоняются. Это намеренно ограниченный
профиль формата, а не обещание поддержки всех будущих KDF.
[Независимый корпус KD2 и первичные источники](../../tests/fixtures/telegram-desktop-kdf/README.md).
На этих35 собственных входах прежний читатель9195d41 не открывал ни одной
современной обёртки; новый открывает9 положительных и отклоняет26 контрольных.
Проверка сборщика и stdin сохраняет два исходных неотправленных черновика из
прежнего корпуса с правильной категорией и неизвестными автором/временем.
Девять обёрток не означают девять новых сообщений или реальных профилей.

Перед чтением проверяются рабочие копии и SHA256 исходников; SQLite DB/WAL/SHM
сохраняются согласованно. Полный проверенный прежний WAL-снимок может содержать
запись, которой уже нет в текущей таблице. Такая запись получает категорию
предыдущей версии и неизвестный факт удаления. Неатрибутированные свободные
байты не получают ID соседней записи. Имена файлов, теги оформления и URL
предпросмотра не заменяют исходный текст и не открываются как ссылки.

Для Postbox нужна уже читаемая предоставленная копия базы. Этот профиль не
расшифровывает SQLCipher и не извлекает ключи iPhone. Неизвестная версия, обрыв
структуры или несовпадение с t4 отклоняются. При наличии полного проверенного
WAL-снимка можно прочитать прежний текст, отсутствующий в текущей таблице.
[Границы и воспроизводимые проверки Postbox](../../tests/fixtures/telegram-postbox/README.md).

На новых собственных входах опубликованный исходный обработчик5684800 получил
0 записей; новый исходный обработчик получил 11: 3 запланированные Android
(одна с пустым текстом), 2 исторические iOS и 6 черновиков Desktop. Это не 11
реальных чатов или проверенных телефонов. Дополнительно проверены отсутствие и
ошибка кода, явно известное отсутствие кода, неверные ключи и схемы, повреждения,
неподдерживаемые версии и теги, атомарный отказ при повреждении последнего
черновика, реальные WAL/DELETE, поиск, Regex, полный текст и повторный импорт.

Контрольный корпус создают независимо от читателя: закреплённые Java-сериализаторы
Telegram, настоящий Qt5 `QDataStream` и SQLite. Профили привязаны к конкретным
[первичным исходникам и SHA](../../tests/fixtures/telegram-platforms/README.md).
Текущие проверки относятся к исходному коду и контролируемому stdin/UI-протоколу.
Пересборка переносимого обработчика, весь готовый комплект, публикация и реальные
Android/iPhone/Desktop устройства этим этапом ещё не подтверждены.
