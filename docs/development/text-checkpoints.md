# Продолжить текстовый поиск после сбоя

При запуске через `RecoveryPipeline` текстовый проход сохраняет собственную
позицию внутри образа. Контрольная точка связывает SHA256 и размер образа,
запрос, исполняемый код, позицию и ведомость найденных фрагментов. Ссылка и SHA
неизменяемого поколения записываются в `recovery-session.json`.

После отмены или завершения рабочего процесса следующий запуск проверяет эту
связь и продолжает текстовый проход с сохранённой позиции. Перекрытие читается
из образа заново, чтобы не потерять строку на границе блоков. Уже проверенные
файлы повторно не записываются. Общая проверка SHA256 всего образа перед
продолжением сессии сохраняется.

## Сначала план, затем файлы

Поколение `text.state/checkpoint-*.json` содержит ожидаемые пути, смещения,
исходные кодировки, размеры и SHA файлов. Родитель подтверждает поколение
**до** публикации новых файлов.

- Сбой до подтверждения оставляет прежнюю контрольную точку действительной.
- Сбой после подтверждения может оставить недописанный или ещё отсутствующий
  файл. Его байты заново извлекаются из подтверждённого участка исходного образа.
- Изменённый существующий файл или неизвестный выходной файл останавливает
  продолжение. Рабочий результат не перезаписывается догадкой.
- Отказ записи родительского состояния откатывает ссылку и в памяти. Повтор
  сохранения того же поколения действительно записывает его на диск.

Обычно позиция сохраняется через 8 МиБ. Блок с новыми находками подтверждается
раньше, перед их публикацией. После успешного подтверждения остаются текущее и
предыдущее подтверждённые поколения. Размер состояния ограничен 16 МиБ,
ведомость — 5000 фрагментами.

## Границы

Фрагмент текста не считается восстановленным документом или подтверждённым
сообщением: автор, чат, дата и факт удаления остаются неизвестными. Изменение
запроса, образа или исполняемого кода требует отдельного запуска. Старые сессии
без внутренней контрольной точки безопасно повторяют незавершённый текстовый
проход с сохранением прежних результатов.

Публичный вызов `RawTextSearch.Recover` без родительского callback остаётся
доступным для простых проходов. Устойчивое продолжение включается конвейером.
Остальные методы используют собственные точки либо повторяют незавершённый
проход; эта реализация не добавляет курсор автоматически каждому алгоритму.

`TextCheckpointTests` проверяет настоящие отмену, завершение собственного
процесса, продолжение курсора, восстановление отсутствующего файла и отказ
при изменённом результате. `SessionCheckpointSaveTests` воспроизводит отказ
сохранения ссылки и повтор той же генерации. Все входы — обычные созданные
тестом файлы; физическое отключение USB и потеря питания не моделировались.
