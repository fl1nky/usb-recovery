# Поиск и полный текст локальных сообщений

В разделе Telegram запрос ищется по полному тексту архива. Если запись длиннее 65 536 символов, результат показывает участок вокруг настоящего совпадения. «Полный текст» открывает сообщение частями; доступны начало, предыдущая и следующая части и возврат к совпадению

Все слова обычного запроса должны присутствовать в сообщении. Regex использует ограничение времени. Координаты считаются в символах Unicode; переносы строк и символы вне BMP не сдвигают найденный текст

## Проверка выбранной записи

`search` выдаёт `archive_record_key`: тип JSONL/SQLite, позицию и SHA256 исходной записи. Операция `message_page` принимает этот ключ, `text_offset` и `limit` до 65 536. Ключ не является путём; обработчик читает только `messages.jsonl` или `chat-index.sqlite` выбранного готового архива

При изменении записи требуется повторный поиск. SQLite открывается только для чтения, без создания WAL/SHM; незавершённый индекс с непустым WAL не используется для постраничного чтения. Поддерживаются записи до 4 МиБ и индекс до 8 ГиБ. Пароль, сетевое подключение и установленный Python для просмотра готового архива не требуются

Некорректный Unicode в тексте исключает эту запись из выдачи; корректные записи остаются доступны. Неисправные поля происхождения показываются как неизвестные. Содержимое сообщения при этом не подменяется

## Проверки

`ArchiveTextTests.py` и независимый `ArchiveTextAuditTests.py` проверяют JSONL/SQLite, отпечаток записи, Unicode, ограничения и неизменность источника. `ArchiveTextPortableTests.cs` проходит через настоящий собранный helper. `ArchiveTextUiTests.ps1` и `ArchiveTextProtocolAuditTests.ps1` используют отдельные искусственные обработчики для проверки интерфейса, отмены и отклонения некорректных ответов; их результаты не считаются испытанием настоящего helper

Полный текст в архиве подтверждает только наличие этих байтов в доступном источнике. Он сам по себе не подтверждает удаление сообщения или полноту переписки
