# Сохранившиеся журналы SQLite Telegram

Анализ локального источника распознаёт доступный `-journal` рядом с базой и отдельный журнал, в том числе по сигнатуре. Журнал может содержать старые байты, которых уже нет в текущей базе. Он не гарантирует наличие удалённой переписки

В интерфейсе используется прежняя кнопка «Анализировать»; для предоставленной копии выбирается «Источник…». Найденный текст доступен обычному поиску, Regex и просмотру полного сообщения

## Что считается находкой

| Доступные данные | Результат | Что остаётся неизвестным |
|---|---|---|
| Все исходные страницы, старая схема, корректная SQLite и согласованные SQL/TL ключи | Самостоятельный снимок, категория «из резервной копии» | Текущее состояние аккаунта, commit/hot-state и факт удаления |
| Частичный журнал с полным поддержанным TL-телом | Текстовый фрагмент, кандидатные TL-поля отдельно | Чат, автор, идентификатор сообщения, дата и удаление |
| Частичный журнал с целой SQLite overflow-цепочкой | Полный найденный текст как неатрибутированный фрагмент | Та же принадлежность; имя соседней базы её не устанавливает |
| Полный физический снимок читаемого JSON-архива без native SQL/TL-связей | Текст сохраняется как fragment, `archive_text_from_rollback_snapshot` | JSON-поля не подтверждают чат, автора, дату или принадлежность Telegram |
| Неподдержанный или повреждённый журнал | Замечание; допустимый проверенный префикс может дать фрагменты | Полный снимок не заявляется |

Для явно выбранного дампа сохранён отдельный общий поиск текста/TL. Такие находки не получают подтверждение журнала, если его структура не прошла проверку. Один исходный target может присутствовать как запись самостоятельного снимка и как отдельный неатрибутированный фрагмент; это не две восстановленные переписки

## Как устроена обработка

`copy_sqlite_sidecars` копирует и перепроверяет DB/journal/WAL/SHM до открытия SQLite. Рабочий journal переименован в `.rollback-journal`: SQLite не получает возможность автоматически replay/delete единственную копию evidence

`sqlite_rollback.py` независимо читает заголовки, размеры, положительный конечный `nRec`, nonce и sparse32 checksum каждой страницы. У всех сегментов должна совпадать geometry. Дубликаты страниц, повреждённые записи, изменение источника и превышение лимитов не превращаются в успешный полный snapshot

Полный before-image создаётся только из всех страниц1..N, включая старую page1/schema. Страницы из нынешней DB не подставляются. Затем выполняются immutable SQLite integrity и строгие поддержанные SQL/TL проверки. Snapshot identity привязана к SHA256 журнала, а не к соседнему аккаунту

Qualified native proof устанавливает только внутренний результат SQL/TL-проверки. Самозаявленные JSON-поля `record_kind`, `application_confirmed` и идентификаторы этого не заменяют. Полный физический SQLite-снимок может содержать полезный неатрибутированный текст; его SHA сохраняется без повышения достоверности записи

`sqlite_rollback_records.py` извлекает частичные TL-кандидаты. Для overflow требуется geometry из старой page1, корректное leaf-cell framing и вся ограниченная pointer-chain внутри проверенных страниц журнала. Отсутствие page1 или звена не исправляется догадкой. Даже собранная полная ячейка без полного контекста остаётся фрагментом с неизвестными идентификаторами

Публикация следует за проверкой неизменности источника. Iterator сверяет canonical descriptors и SHA до выдачи и после исчерпания; неполный iterator не подтверждает окончательную проверку

## Происхождение и перенос архива

Сообщение содержит journal SHA, отдельный snapshot SHA при его наличии, вид доказательства, неизвестные hot/current/authenticity состояния и ссылку на карту

Карта сохраняется один раз в `provenance/rollback/{journalSHA}.json`; SHA карты находится в `rollback_page_map_sha256`. В ней — номера страниц, заголовки, физические смещения и хеши исходных page bytes. Для overflow добавляются ограниченные `rollback_payload_*` диапазоны и SHA собранного SQL payload

`rollback_provenance.py` проверяет структуру display metadata без открытия исходного телефона или DB. Поиск не аутентифицирует содержание переписки. Частичный proof принудительно сохраняет неизвестные чат/автора/дату/ID и категорию fragment даже при противоречивых полях предоставленного архива

Повторный импорт JSONL/SQLite-архива переносит карты и дополнительные источники после проверки безопасного пути/размера/SHA. Если карта отсутствует или изменилась, текст сохраняется как импортированная запись, прежнее provenance отмечается недоступным; ссылка не выдаётся за новую доступную карту

Для acquisition-копии телефона сохраняются исходные object Id/URI/относительный путь. ZIP members имеют собственные SHA/размер/Id и отдельные `container_sha256`, `container_source_id`, `container_source_file`; временная папка не становится опубликованным источником. Предоставленный per-file SHA проверяется, неизвестный SHA не угадывается

## Ограничения

- SQLite sparse32 checksum проверяет только часть байтов. Она не является подписью, не аутентифицирует текст и не подтверждает номер страницы или SQL-ключ
- По одному статическому файлу нельзя установить hot-state, commit и факт удаления. PERSIST может обнулить заголовок после завершения транзакции
- Нулевой/sentinel `nRec`, super-journal и неизвестные варианты не интерпретируются как полный подтверждённый снимок; внешние имена super-journal не открываются
- Вход журнала ограничен256МиБ,65536records/8192headers/131072initialpages; snapshot512МиБ и5млнSQLite-операций
- Partial-проход:256МиБ чтения,200000общих rawTL/cell/BLOB попыток,4МиБ payload,4096звеньев цепочки,20000фрагментов/64МиБ текста. Общий fragment budget разделяется между источниками
- Шифрование `tdata`, закрытые области телефона, неизвестные TL/SQLite-схемы и получение новых memory dumps этим модулем не добавляются
- Наличие заголовка или readable fragment не означает, что исходная переписка восстановима целиком

Формат проверен по первичным источникам SQLite: [rollback journal](https://sqlite.org/fileformat2.html#the_rollback_journal), [locking](https://sqlite.org/lockingv3.html#the_rollback_journal), [pager3.53.1](https://github.com/sqlite/sqlite/blob/version-3.53.1/src/pager.c)
