# Восстановление видео с разрывами внутри сэмплов

Новый резервный путь собирает MP4/MOV из сохранившихся блоков, даже когда разрыв проходит внутри AVC, AAC или `moov`. Он включается после неудачного поиска целых чанков. Это проверка структуры и источников байтов, а не расшифровка или доказательство подлинности видео.

Таблицы контейнера задают смещения и размеры сэмплов, но не их контрольные суммы. Смещения `stco/co64` относятся к самому файлу. [Apple: chunk offsets](https://developer.apple.com/documentation/quicktime-file-format/chunk_offset_atom), [sample tables](https://developer.apple.com/documentation/quicktime-file-format/sample_table_atom).

Для размеров блока 512–65536 байт программа ищет положения, подтверждённые сохранившимися заголовками контейнера/видео или полным синтаксическим разбором AAC-LC. Начала физических блоков должны иметь согласованное смещение относительно 512-байтного сектора. Каждый блок требует собственной опоры. Затем проверяются все сэмплы, переходы между блоками, полное покрытие файла и отсутствие повторного использования физических диапазонов. Разные допустимые результаты означают неоднозначность; выбор «лучшего» результата отсутствует. Одинаковые копии взаимозаменяемы только при одинаковых ограничениях пересечения.

Варианты сборки `moov` проверяются вместе со всем файлом до публикации. Одинаковые байты метаданных с разными физическими картами сохраняются как отдельные варианты. В том числе проверяется структура вложенных `meta/ilst`; неподдержанный вариант метаданных может остаться невосстановленным.

## Границы

- Резервная сборка: файл до 16 МиБ, до 4096 блоков, 8192 состояний, 32 МиБ сохранённых блоков. Обычный поиск целых чанков сохраняет прежние пределы.
- Ремонт метаданных: до 64 КиБ, восьми фрагментов, 64 физических вариантов и миллиона проб. Общие ограничения чтения и отмена остаются действующими.
- Содержимое AVC/HEVC после проверенных заголовков, ссылки на другие кадры и PCM не декодируются. AVC проверяет упаковку NAL; HEVC дополнительно проверяет поддержанные параметры и заголовки срезов. Успешная проверка структуры не обнаруживает любую порчу полезной нагрузки.
- Произвольные разрывы вне проверяемых блоковых гипотез, участки без опор, отсутствующие байты, HE-AAC и `moof` остаются неподдержанными. Данные не дополняются нулями, контейнер не перемонтируется.
- При исчерпании предела результат `limited`, без заявления об уникальности. Независимый контроль на образе 64 МиБ с хвостовым `moov` достиг предела поиска; наличие всех исходных байтов не гарантирует завершённое восстановление.

Результат сохраняет `iso_bmff_structural_candidate`, `PayloadAuthenticated=false`, `DeletionConfirmed=false`. Новая ветка указывает `AudioSearch=allocation_unit_syntax`, а каждый диапазон результата ссылается на реальные байты образа. Имя — хеш содержимого, исходное имя неизвестно.

## Проверки

На сохранённом корпусе версии 6 оба ранее неподдержанных случая с блоками 4 КиБ теперь совпадают с полным исходным SHA256, каждым декодированным кадром и всем PCM. Публичные материалы и исходные образы версии 6 сохранены.

Новый независимый корпус содержит 17 случаев реального FFmpeg: AVC с B-кадрами, 192×128/320×192, 44,1 кГц mono/48 кГц stereo, передний/хвостовой `moov`, блоки 4/8/16 КиБ, изменённые физические смещения, нулевой/случайный фон, два видеотрека и разрыв четырёхбайтной длины NAL. Девять результатов совпадают с оригиналами побайтно. Ещё три — намеренно изменённые текущие данные: AAC с другой громкостью, непрозрачная порча видеоданных и копия продолжения метаданных внутри видеоданных; они остаются неподтверждёнными кандидатами. Последний случай проверяет, что равные метаданные с разными ограничениями физического пересечения не теряются при объединении копий. Пять случаев с неоднозначностью, утратой, перезаписью или неподдержанной геометрией не публикуют файл. Для девяти оригиналов и изменённого AAC независимо проверены все кадры и PCM; проверка декодирования двух повреждённых видеокандидатов не заявляется.

Отдельные наборы проходят 826 новых проверок, 674 прежних проверки медиа, 527 AAC и 163 HEVC с независимым декодером. Это проверки движка на синтетических обычных файлах. Они не являются проверкой интерфейса, всего конвейера, реальных накопителей или сравнением с платными программами.

Офлайн-корпус: `tests/fixtures/media-units`, 17 сжатых образов с хешами и происхождением. Исходный генератор использует FFmpeg только на машине разработчика. Восстановлению передаётся путь к образу; эталонная карта из manifest в движок не поступает.

```powershell
python tests/build_media_unit_fixtures.py --extract tests/fixtures/media-units --destination .build/media-unit-fixtures-current
```

Запуск `FragmentedMediaUnitRecoveryTests` получает корень проекта, необязательный путь к распакованному корпусу и `--decode` для проверки через закреплённый FFmpeg. Без `--decode` Python, FFmpeg и сеть при выполнении тестов не требуются. При прямой компиляции исходников необходимо включать новый `FragmentedMediaRecovery.Units.cs` вместе с основным файлом и AAC/HEVC-модулями.
