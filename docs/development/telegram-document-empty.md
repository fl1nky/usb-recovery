# Legacy document-reference text

This source change reads surviving text from one previously rejected Telegram Android format: `TL_messageMediaDocument_layer74` (`0x7c4414d3`) containing `TL_documentEmpty` (`0x36f8c871`). It preserves outer `message` and distinct `media.legacy_caption` through the existing native text pipeline. It does not recover a document/video file or retrieve an attachment.

The wire contract is pinned to [Telegram Android 4de548e](https://github.com/DrKLO/Telegram/blob/4de548e79fed27f1a66fbdff84223321838fe925/TMessagesProj/src/main/java/org/telegram/tgnet/TLRPC.java): flags bit0=document, bit1=caption, bit2=TTL in that order. Other flags and document constructors fail closed. Document IDs are opaque signed int64 values; explicit zero and negative values are retained. When bit0 is absent, no document ID is claimed from nonexistent bytes. TTL remains the reader's explicitly restricted nonnegative int32 subset, matching its existing photo policy.

Complete TL/tail consumption, UTF‑8/padding/length limits and the caller's SQL mid/date/uid/peer/scope/body checks are unchanged. Unknown encrypted/full-document formats are not skipped. Local paths, network links, access hashes and file references are not followed. No new `media_v4` type or photo allowlist entry is accepted.

The media adapter publishes both checked text roles with `media_kind=document`, `media_status=document_reference_only`, zero thumbnails and no attachments. An observed document ID is an exact decimal string; an absent ID remains unknown. The HTML archive and Windows interface label legacy captions as attachment captions and explain that file bytes, name and subtype are unknown. A completely empty document record is not published as a message. Successful parsing indicates a surviving record, not proof of user deletion.

The independent official Java oracle has 167 BLOBs; native SQLite fixtures cover current, committed WAL, residual byte replay, roles, SQL mismatches, Unicode, keyword/Regex search and untrusted reimport. The documented 188-byte original witness failed before the change with `TL_UNSUPPORTED_MEDIA`; its eight-byte-different photo control passed. See [fixtures](../../tests/fixtures/telegram-document-empty/README.md), [factory](../../tests/build_telegram_document_empty_fixtures.py) and [tests](../../tests/TelegramDocumentEmptyTests.py).

The rebuilt portable helper and Windows app passed the new [runtime suite](../../tests/TelegramDocumentEmptyPortableTests.cs): 253 exact text fields, signed/zero/absent IDs, account scopes, WAL versions, residual byte replay, search, full text, canonical reimport and rejection of forged provenance. The complete offline gate passed 60 quality suites / 69,893 assertions, Telegram 4/137 and USB pipeline 1/16. Python was absent from PATH, outbound access was blocked for tested programs, temporary rules were removed and source bytes remained unchanged. These are owned fixtures, not a real-phone test or a fresh paid-tool comparison.
