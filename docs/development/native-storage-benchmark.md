# Проверить восстановление без окон

Бенчмарк запускает по одному файловому движку на обычном образе. Он не открывает
диски компьютера, не монтирует образы и не запускает интерфейс. Каждая находка
проверяется SHA256 исходного содержимого из внешней ведомости.

## Запустить локально

Из подготовленного checkout на Windows, с разработческим Python 3.12:

```powershell
.\scripts\build-app.ps1
.\scripts\build-benchmark-driver.ps1
python tests/benchmarks/native_storage.py prepare-ext4 --destination .build/native-ext4
python tests/benchmarks/native_storage.py run --corpus .build/native-ext4 --destination .build/native-ext4-results --driver .build/app/NativeStorageBenchmark.exe --require-exact
```

Выбирай новые каталоги результатов. Исходные образы, ведомость, приложение и
драйвер сверяются до и после запуска. Подменённые пути, ссылки и несовпадающие
хеши останавливают проверку. Драйвер имеет `asInvoker` и читает только файлы,
перечисленные в проверенной ведомости.

## Откуда берутся данные

- Локальный набор использует закреплённые образы ext4, созданные e2fsprogs.
  Контролируемые повреждения и изменения метаданных явно помечены в происхождении.
- Задание `Native storage corpus` создаёт FAT12/16/32 средствами dosfstools и
  mtools в отдельном Linux runner. `mtype` подтверждает исходное содержимое перед
  штатным удалением `mdel`. Windows runner затем запускает наш реальный движок.
- Ведомость сохраняет версии и SHA утилит, журнал команд, исходные SHA и тип
  контроля. Успех искусственного повреждения не называется проверкой настоящего
  аппаратного отказа или физического носителя.

## Читать результат

`run.json` содержит точные совпадения, пропущенные эталоны, отдельные отрицательные
контроли, время и пиковый рабочий набор процесса. Запускаются только файловые
движки C#, без дочерних обработчиков; область измерения памяти записана явно.
Время движка отделено от времени всего процесса с проверками SHA.

Повтор одинакового содержимого учитывается один раз. При неполной ведомости
посторонний кандидат остаётся неклассифицированным. Ложные находки считаются
только в явно полном отрицательном контроле. Ошибка движка сохраняется в отчёте;
`--require-exact` дополнительно требует все эталоны и ноль находок в отрицательных
контролях.

Это проверка качества на указанном корпусе. Она не устанавливает общий рейтинг,
процент превосходства над платными программами или надёжность настоящего USB.
