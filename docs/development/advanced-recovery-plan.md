# План сложных частей восстановления

База проверки: `32cb509`, ветка `feat/forensic-expansion-parallel`, 23 ноября 2026.
Старые результаты других веток не подтверждают возможности этой сборки.
Работа выполняется без управления экраном и реальных устройств.

| Порядок | Работа | Условие завершения |
|---|---|---|
| 1 | Достоверность Telegram: отделить неподтверждённые SQLite-фрагменты от сообщений, сохранить происхождение, убрать выдуманные идентификаторы и вывод об удалении | Посторонняя SQLite-база не создаёт сообщений; JSON, CSV, HTML и временная шкала сохраняют различие |
| 2 | Продолжение поиска: инвентаризация checkpoint по каждому движку, привязка к содержимому входа и параметрам, атомарная запись, незавершённые файлы | Отмена и принудительное завершение собственного тестового процесса на каждой границе; повторное продолжение даёт те же байты без потерь и дублей; изменённый источник отклоняется |
| 3 | Сложные фото/видео: фрагментированные JPEG, MP4/MOV, несколько разрывов, неоднозначные сочетания | Независимые положительные и отрицательные образцы; точное сравнение файлов и декодированных данных; частичный результат явно обозначен |
| 4 | Локальные Telegram DB/WAL: адаптеры конкретных схем Android/iPhone/Desktop, история транзакций и overflow | Версия/таблица/запись подтверждены; незафиксированный WAL не становится текущим сообщением; неизвестные поля остаются неизвестными; входные копии неизменны |
| 5 | Сложные хранилища: сначала аудит APFS/RAID/BitLocker, затем выбранные неподдержанные случаи | Для каждого случая отдельный независимый образ и побайтовый эталон; неверный ключ, повреждение и неподдержанная версия отклоняются |
| 6 | Выпуск | Полные исходные и packaged проверки на одном SHA, актуальный CI, повторяемая сборка, проверенный ZIP, таблица ограничений |

Первый этап исправляет новый C# forensic triage. Он не заменяет существующие
Python-адаптеры Telegram: их возможности и тесты учитываются отдельно.
Наличие текста и числа, похожего на дату, не устанавливает приложение,
автора, чат, направление сообщения или факт удаления.

Перед этапом 2 необходимо сопоставить сохранённые ветки. Например, коммит
`231df13` с продолжением обработки истории ext4 существует локально, но не
является предком этой базы. Переносить нужные изменения с проверкой зависимостей
и конфликтов; не реализовывать их заново и не считать автоматически принятыми
на другой ветке. Удалённые рабочие каталоги не означают потерю Git-коммитов.

Проверки не должны снова раздувать каталог: маленькие генерируемые fixtures,
одна рабочая ветка, отдельный временный каталог, удаление только собственных
временных данных. Отчёты и необходимые образцы сохраняются, большие копии
сборок без необходимости не создаются.

Реальные USB-сбои, телефоны, визуальная проверка интерфейса и сравнение через
окна платных программ остаются отдельными отложенными испытаниями. Без них
нельзя заявлять превосходство над конкурентами или готовность всех форматов.

## Первый пакет: границы доказательств Telegram

В C# triage `ParseDatabase`/`CarveDatabase` возвращают `TelegramTextFragment`,
а не сообщения. В JSON фрагменты находятся в `TextFragments`; `Messages`
зарезервирован для результатов подтверждённых адаптеров. В CLI добавлен
`text-fragments.csv`. Неизвестные чат, автор и дата не угадываются. Наличие
пароля Desktop в этом модуле неизвестно (`HasPasscode: null`).

В веб-API фрагменты находятся в `textFragments`, счётчик — `totalTextFragments`.
Прежние `deletedMessages`/`isDeleted` заменены на `carvedMessages`/`isCarved`:
нахождение записи в свободной области само по себе не доказывает удаление.
Текст выводится буквально, не как HTML. CSV защищает начальные формулы
апострофом; точный исходный текст остаётся в JSON. Фрагменты без достоверной
даты не добавляются в хронологию сообщений.

Локально прошли 55 проверок TelegramParser, 36 CourtReportGenerator, 61
SqliteCarver и 24 интеграционные проверки настоящего CLI на базах, созданных
через SQLite. Отдельно прошёл JavaScript renderer на имитации DOM. Обычная
сборка приложения выполнена с предупреждениями как ошибками.

Общий LocalWebServerTests не прошёл: среда выбрасывает
`PlatformNotSupportedException` в конструкторе `System.Net.HttpListener`.
Это ограничивает проверку HTTP; имитация DOM не заменяет настоящий сервер
или визуальную проверку. Полная приёмка продукта и новая portable-сборка
этим пакетом не заявляются. Новый CI workflow проверяет этот пакет отдельно.

Оставшиеся ограничения triage: каталог ищет только `*.db` и ограничен 20
базами; нет распознавания схем сообщений, WAL-снимков и продолжения этого
сканирования после сбоя. Они остаются работой этапов 2 и 4.
