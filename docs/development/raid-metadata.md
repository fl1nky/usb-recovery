# Чтение разметки RAID

`RaidMetadataProbe` читает предоставленные завершённые локальные RAW-образы. Физические диски, драйверы контроллеров и mdadm не открываются. Исходные файлы не изменяются.

## Поддержка

| Формат | Результат |
|---|---|
| Linux MD 0.90 / 1.0 / 1.1 / 1.2 | Поддерживаемые чистые схемы существующего сборщика; неизвестные features, reshape и конфликтующие поколения отклоняются |
| SNIA DDF 1.2, сектор 512 байт | Один простой виртуальный диск RAID0, RAID1 или поддержанный RAID5; проверенные ссылки участников, размеры, поколения и резервные копии |
| Intel IMSM, сектор 512 байт | Проверка настоящего MPB и отображение ограничения. Готовая конфигурация не выдаётся: RAW-образ не содержит доказанной привязки к серийному номеру текущего диска |
| Windows Storage Spaces | Сборка не поддерживается. Старый локальный заголовок `MSFT` не считается доказательством настоящего формата |

`Group.Configuration` доступна только при `Status == "candidate"`. Она требует проверки человеком. `MetadataOnly` и `RequiresReview` остаются `true`, `DataIntegrityEstablished` — `false`. Сборщик отдельно проверяет зеркала/P/Q; при недостатке избыточности это не доказывает правильность восстановленных байтов.

## Настоящий DDF

Многобайтные поля читаются в big endian; GUID имеет 24 байта. Anchor последнего сектора содержит ссылки на основной и резервный заголовки. Читаются отдельные Controller Data, Physical Disk Records, Virtual Disk Records, Configuration Records и Physical Disk Data. Проверяются CRC каждой используемой структуры и каждой конфигурационной записи. CRC использует отражённый регистр с начальным нулём без завершающего дополнения; поле CRC при расчёте заполнено `ff`.

Роль образа выводится из GUID/reference его Physical Disk Data и последовательности физических ссылок VD Configuration Record. Имя файла, входной порядок и номер записи физического диска не задают роль. Проверяются Starting Block, Block Count, VD Size, настроенная ёмкость всех участников, отсутствие пересечения с метаданными и совпадение карт/таблиц участников между образами. Для RAID5 qualifier 0/2/3 означает соответственно right-asymmetric / left-asymmetric / left-symmetric.

Поддерживается только закрытая согласованная разметка. Различающиеся основной/резервный экземпляры, foreign/open/dirty/rebuild, дополнительные remapping/vendor sections, сложный secondary RAID, несколько томов, неизвестные layouts и DDF RAID6/10 не дают готовой конфигурации. Missing roles задаются явно; разрешённые деградированные RAID1/5 проверяются отдельно. Здоровое состояние самой записи не доказывает, что все RAW-компоненты предоставлены.

Ограничения чтения: MD до 4 КиБ на суперблок и 64 КиБ на образ; DDF до 1 МиБ наблюдаемых метаданных и до 2 МиБ с повторной проверкой на образ. Каждая секция ограничена 512 КиБ. Проверяются границы секций, file identity/size/mtime, reparse paths и hardlinks. `SourceUnchanged` относится к проверенным метаданным и идентичности файла во время probe.

## IMSM и Storage Spaces

IMSM anchor располагается в предпоследнем 512-байтовом секторе. Продолжение MPB хранится **перед** anchor. Разборщик проверяет объявленный размер до 64 КиБ, аддитивную сумму, generation в `0x2c`, таблицу 48-байтовых дисков в `0xd8`, структуру volume/map и настоящую таблицу 32-битных ordinal. Неподтверждённая связь текущего образа с физическим диском всегда блокирует конфигурацию: настоящий MPB одинаков на участниках, а mdadm получает серийный номер отдельно от устройства. Автоматически подставлять dev_number или входной порядок нельзя.

Storage Spaces требует отдельного проверенного разбора настоящих баз метаданных и распределения экстентов. Прототип с `MSFT` и непосредственно записанными полями RAID не является такой реализацией. R06 остаётся частично выполненным.

## Проверка и происхождение образцов

- `tests/fixtures/raid-md`: опубликованные образы dissect.volume и явно производные MD-контроли; прежние проверки остаются отдельными.
- `tests/fixtures/raid-controller`: 8 неизменённых upstream gzip-образов настоящего DDF0/1/5 из [fox-it/dissect.volume, commit d2da189](https://github.com/fox-it/dissect.volume/tree/d2da189112cae3a627f96d9de78341193eb6dc52/tests/_data/ddf), лицензия AGPL-3.0. URL, compressed/raw SHA256, длины и роли закреплены в manifest.
- 15 прежних синтетических IMSM/DDF/MSFT образцов сохранены только как отрицательные контроли `invalid_legacy_prototype`: ни один не должен давать конфигурацию.
- `raid_controller_fixture_generator.py --extract SOURCE DESTINATION` извлекает закреплённые байты офлайн, проверяя размер и SHA256. Он не создаёт якобы настоящие контроллерные метаданные.
- `RaidControllerRecoveryTests.cs` проверяет полные SHA256 DDF0/1/5 и все разрешённые варианты одного отсутствующего участника. Независимые ожидаемые блоки взяты из [upstream test_ddf.py](https://github.com/fox-it/dissect.volume/blob/d2da189112cae3a627f96d9de78341193eb6dc52/tests/ddf/test_ddf.py): нумерованные 4-КиБ блоки. Полный SHA256 дополнительно получен чтением независимого `DDFVirtualDisk.open()` ровно по полосе.
- Установленный dissect.volume 3.18 имеет ошибку многополосного чтения в `RAID456Stream._read`: используется `read(length)` вместо `read(read_length)`. Эталон рассчитан запросами размером одной полосы; код внешней библиотеки не изменялся. Это не новый native RAID5 filesystem/device тест.

Источники структуры: [SNIA DDF, разделы 5.2–5.9](https://www.snia.org/sites/default/files/SNIA_DDF_Technical_Position_v2.0.pdf), [mdadm super-ddf.c](https://github.com/md-raid-utilities/mdadm/blob/main/super-ddf.c), [mdadm super-intel.c](https://github.com/md-raid-utilities/mdadm/blob/main/super-intel.c). Принята только указанная ограниченная схема DDF1.2; ссылка на DDF2.0 не означает его поддержку.
