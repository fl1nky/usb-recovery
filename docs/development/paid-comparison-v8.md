# Опубликованная V8 и сохранённые результаты платных программ

Приложение из выпуска `v2026.10.31-large-video-telegram` повторно прошло полный `RecoveryPipeline` на тех же пяти образах, для которых ранее получены результаты R-Studio Demo. Два из них также имеют сохранённые экспорты DMDE Free. Файлы конкурентов не менялись; они заново оценены тем же декодером. Нового запуска платных программ в этом сравнении не было

| Исходный образ | Recovery V8 | R-Studio Demo | DMDE Free |
|---|---|---|---|
| Целый JPEG | Точный оригинал | Точный оригинал | Совпадают пиксели, файл с лишним хвостом |
| JPEG с разнесёнными restart-фрагментами | Точный оригинал | Повреждённый кандидат | Повреждённый кандидат |
| AVC MP4 с двумя дорожками | Точный оригинал | Повреждённый кандидат | Не проверялось |
| MJPEG MOV с двумя дорожками | Точный оригинал | Повреждённый ролик и отдельные JPEG | Не проверялось |
| PNG с разнесёнными блоками | Точный оригинал | В сохранённом полном сканировании находок нет | Не проверялось |

Итого по пяти целевым файлам: **V8 — 5/5 точных оригиналов, R-Studio — 1/5**. На двух общих примерах **V8 — 2/2 точных**, DMDE — **0 точных и 1 эквивалентный по пикселям**. Эквивалентный файл DMDE содержит исходный JPEG целиком с дополнительным хвостом; полезное изображение восстановлено

Это узкое сравнение собственных образов по 8 МиБ. Оно не даёт общего процента восстановления, рейтинга скорости или доказательства превосходства на пользовательских носителях. R-Studio Technician Demo `9.5.191861` и DMDE Console Free `4.4.4.842` — версии сохранённых опытов, не заявление о последних доступных версиях. Ограничение trial не мешало проверенным эталонам; UFS Explorer и новые большие видео/Telegram здесь не испытывались

- Исходный полный manifest `corpus-02`: `da682d094b53e2a326b633e099e88352c97240c0a0b736a0ea382585b1f73623`. Выбор пяти случаев не менял manifest
- Хеши 835 файлов подготовленного runtime, 29 файлов корпуса и 20 старых выгрузок до/после совпали. Независимо проверены 176 артефактов стадий и классификация 52 кандидатов; повторное декодирование выполнялось оценщиком, независимый аудит его не запускал
- В каждом случае все 10 выбранных стадий отмечены завершёнными; общий статус пяти сессий — `finished_with_warnings`. Невыбранные методы, включая ext4, этим опытом не проверялись. Лишние JPEG внутри MOV автоматически не считаются ложными находками

Приватных профилей, реальных устройств и исполняемых файлов платных программ в доказательствах нет. Обновлён только сравнительный отчёт; опубликованный ZIP и его исполняемые файлы остались неизменными

## Воспроизведение

Исходная генерация восстанавливает 309 файлов побайтно. Дополнение `verification-02` сохраняет исправленный инструмент повторного расчёта: он использует проверенный оценщик из репозитория и не выполняет Python из архива. Проверены 11 защитных сценариев и повторный расчёт 7/7 сохранённых результатов. Полный комплект с дополнением — 327 файлов, 66 551 213 байт; контрольные суммы совпали

Из корня подготовленного проекта, с разработческим Python и закреплённым FFmpeg:

```powershell
python tests/benchmarks/export_media_comparison.py --restore tests/benchmarks/evidence-v8-comparison/complete-proof.json --out .build/v8-comparison-replay-01
python tests/benchmarks/export_media_comparison.py --rescore .build/v8-comparison-replay-01 --out .build/v8-comparison-rescore-01 --ffmpeg tools/benchmarks/ffmpeg/ffmpeg-9.0.2-essentials_build/bin/ffmpeg.exe
```

Повторный расчёт читает сохранённые результаты и запускает только декодер, без нового поиска Recovery/R-Studio/DMDE. Поля оценок совпадают, кроме перемещённых путей, хеша производного run-файла и нестабильного текста диагностик декодера. Исходные диагностические строки сохранены.
