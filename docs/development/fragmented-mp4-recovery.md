# Сборка фрагментированного MP4

Этот путь собирает ограниченный вид native fMP4 из образа: сохранённый заголовок
и целые пары `moof+mdat`, физический порядок которых изменился. Нужен сохранившийся
индекс `mfra/tfra/mfro`. Произвольные разрывы внутри пары пока не поддерживаются.
Описанные проверки относятся к исходному C# движку, а не к реальным устройствам.

В анализе образа используется существующий способ сборки фрагментов MP4/MOV.
Результат сохраняется как кандидат с именем по SHA256. Исходное имя, владелец,
факт удаления и наличие потерянного окончания не устанавливаются.

## Что должно сохраниться

| Часть | Проверка | Граница поддержки |
|---|---|---|
| `ftyp` и init `moov/mvex` | Пустые таблицы, самостоятельные ссылки, `trex`, конфигурация AVC | Один видеотрек `avc1`, длина NAL 4 байта; без edit list |
| Целая `moof+mdat` | `mfhd`, `tfhd`, `tfdt`, `trun`, размеры/время и полное покрытие payload | Один `traf/trun`, data offset ровно `moof bytes + mdat header`, последовательность с 1, время с 0, composition offset 0 |
| `mfra/tfra/mfro` | Логические позиции, время, количество частей, размер индекса | Индекс каждой пары указывает её первый sample; обязательный хвост |

Совпавшие идентификаторы и время не удостоверяют принадлежность частей одному
исходному видео. Если несколько полных вариантов дают разные байты, файл не
выбирается. Одинаковые байты с разных мест дают один файл и все проверенные
полные карты размещения. Каталог и экспорт сохраняют эти карты, а исходное
размещение остаётся неизвестным.

Проверяется структура NAL и таблиц, без декодирования восстановленного видео
движком. Изменённые непрозрачные байты могут пройти такую проверку; результат
сохраняет `iso_bmff_structural_candidate`, `PayloadAuthenticated=false` и
`DeletionConfirmed=false`.

При отсутствии индекса или указанной части отчёт имеет `partial`; публичный
конвейер получает обычное состояние незавершённого этапа с пояснением. Исчерпание
лимита даёт `limited`, отмена — `cancelled`. Недостающие байты не дописываются.
Классический MP4/MOV использует прежний путь. Дополнительный поиск `moof/mfra`
включается только после обнаружения целого init с `mvex`.

## Ограничения работы

Не более 256 индексированных пар, 100000 суммарных sample claims во всех
проверяемых вариантах, 8192 состояний поиска, 512 полных карт, 100000 суммарных
extent claims и 512 MiB повторного чтения для карт. Действуют также общие лимиты
движка на размер файла, результаты и проверяемые байты. Переполнение бюджета не
превращается в доказательство единственности.

Образ открывается только на чтение. Для native пути SHA256 всего обычного файла
сравнивается до и после сборки; отмена проверяется во время чтения. Это привязка
наблюдавшихся байтов. Поля предоставленного JSON сами по себе не подписаны и не
аутентифицированы. При наличии локальной recovery session её SHA/размер должны
согласовываться с отчётом; неизвестные или противоречивые источники не получают
подтверждённое положение.

## Воспроизводимые данные

Независимый writer использует зафиксированные FFmpeg/ffprobe и не читает движок.
Он записывает original, сверяет каждый packet с таблицами и декодирует 12 кадров.
Сохранённый native образ содержит все original bytes: пары лежат в порядке 2,3,1.

| Доказательство | Значение | Что устанавливает |
|---|---|---|
| Original | 19774 байта, SHA `9b977c560afa2b120d4b85373494ce9bcdd13328ce299dd5b726eda9c31dcbd8` | Независимые исходные байты |
| Образ | 2 MiB, SHA `a270ed13657d4e346814fa40ec1de01d60380ac6f026f52dd206bde905610d1f` | Тот же вход до/после разработки |
| Source recovery | Один exact original, все шесть исходных диапазонов | Реальная сборка этого примера |
| Мутации в C# тестах | Отдельно помеченные synthetic controls | Чужой track, конкурирующие/одинаковые варианты, повреждения, границы, отмена и лимиты |

Один native пример не означает поддержку всех fMP4, всех чужих потоков, HEVC,
аудио, шифрования, нескольких треков, отсутствующего init/индекса или arbitrary
sample-internal splits. Платные полные версии и реальные устройства этим набором
не сравнивались.

Для разработчика с Python 3.12:

```powershell
python tests/prepare_fmp4_media_fixtures.py
python tests/prepare_fmp4_media_fixtures.py --verify
```

Подготовка проверяет весь набор, SHA/размер каждого файла и собственного preparer,
не меняет старый/частичный cache и не запускает recovery. Отдельный
`build_fmp4_media_fixtures.py` принимает `--destination`, `--ffmpeg`, `--ffprobe`;
бинарные SHA зафиксированы в исходнике. Это developer-only повтор native writer,
не необходимость устанавливать Python для обычного пользователя программы.

Структура: независимый writer/packet/frame oracle → сохранённый образ →
`Recover` → сверка exact bytes/каждой карты → каталог и export. Реальные source
проверки находятся в `Fmp4RecoveryTests.cs`; новые сборки/упаковка/публикация
проверяются отдельно.

Основа формата: [W3C ISO BMFF, разделы 3–4](https://www.w3.org/TR/2024/NOTE-mse-byte-stream-format-isobmff-20240723/).
