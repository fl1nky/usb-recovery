# Старые базы Telegram Android

Поддерживается читаемая локальная база с таблицей `messages` из 12 столбцов официального Android-формата. Проверяются порядок и типы столбцов, `mid INTEGER PRIMARY KEY`, дата и связь SQL-ключей с TL-телом. Одного имени `messages` для распознавания недостаточно

Выбери **Telegram → Источник… → Папка / копия телефона… → Анализировать**. Передай неподвижную копию базы и одноимённые `-wal`/`-shm`, если они сохранились. Затем используй слова или **Regex** и смотри происхождение выбранной строки

## Два разных ключа

У старых каналов SQL хранит `(channel_id << 32) | message_id`. Например, для канала 88 и сообщения 23:

| Поле | Значение |
|---|---|
| `message_id` | `23` — проверенный ID из TL, относящийся к конкретному чату |
| `chat_id` | `-88` |
| `sqlite_stored_mid` | `377957122071` — исходный SQL-ключ |
| `source_record` | `messages(uid=-88,mid=377957122071)`, с номером коммита для WAL-снимка |

Проверяется весь упакованный ключ; отбрасывать его старшие биты недостаточно. Одинаковый публичный ID в разных каналах не объединяет сообщения. Если автор отсутствует в TL, `sender_id` остаётся неизвестным

## Что именно читается

Добавлен текстовый профиль TL114 `0x452c0e65` по закреплённому [официальному Android 6.2.0](https://github.com/DrKLO/Telegram/blob/f424ea165af4e868391b24640d2e715d1a45ce3c/TMessagesProj/src/main/java/org/telegram/tgnet/TLRPC.java). Он читает текст, известные булевы флаги и скалярные поля автора, ответа, бота, просмотров, редактирования, подписи и группы. У этого профиля один счётчик просмотров; следующего счётчика пересылок нет

Именно новый профиль114 отвергает вложенные media/forward/markup/entities/restrictions и неизвестные флаги. Уже поддерживаемые TL-профили продолжают действовать по своим правилам. Полноценный разбор всех старых схем не заявлен

Полный проверенный прежний WAL-снимок может сохранить строку после реального SQLite DELETE. Она относится к категории `previous`; ручное удаление пользователем и состояние облачной истории неизвестны, `deleted=null`. Потерянный ключ свободной ячейки `INTEGER PRIMARY KEY` не подбирается. Изолированное TL-тело в дампе остаётся неатрибутированным фрагментом

## Измеренный результат

Настоящие замороженные helper V7 и V8 прошли одинаковые четыре примера: по пять целевых записей, повторённых для профилей114/118 и обычной базы/WAL. V7 проверенно связала **0 из 20 попаданий**, V8 — **20 из 20**. Это 20 попаданий в конкретных примерах, не 20 разных людей, чатов или независимых сообщений

Все 20 попаданий V8 найдены обычным поиском и Regex; пять отрицательных контролей не выданы за переписку. Версии сообщения и дополнительные источники снимков учитываются отдельно. Независимый расчёт прошёл 76 проверок с намеренно испорченными доказательствами

Измерялся только stdin API helper; приложение, интерфейс и C#-конвейер этим сравнением не проверялись. Платные результаты — `not_tested`. Личные телефоны и профили не сканировались; встречающиеся в доказательствах пути проекта относятся только к собственным сгенерированным примерам
