# PNG с разрывом внутри IDAT

Обычное размещение файла по кластерам может разорвать один блок IDAT. Его заголовок и конец сохраняются, но прежний поиск целых CRC-блоков такой фрагмент не индексировал. Новый путь рассматривает целые блоки и продолжения разорванного IDAT вместе. Полностью непрерывный PNG сохраняет быстрый обычный поиск.

PNG-блоки не обязаны совпадать с физическими секторами, границами строк или DEFLATE. См. [PNG3, структура блоков](https://www.w3.org/TR/2025/REC-png-3-20250624/#5DataRep) и [сжатие IDAT](https://www.w3.org/TR/2025/REC-png-3-20250624/#10Compression).

## Поиск и проверки

Для сохранившегося восьмибайтного заголовка IDAT до 2 МиБ перебираются **все абсолютные 512-байтные границы** внутри блока, после его заголовка. Продолжение вычисляется по объявленной длине и физическому началу проверенного следующего IDAT/IEND. Учитываются также непрерывные цепочки сохранившихся вспомогательных блоков перед IEND в пределах 64 КиБ.

Для перебора срезов окно начала читается один раз на заголовок, окно продолжения — один раз на опору; отдельные проверки целых блоков сохраняются. CRC начала накапливается слева направо, CRC продолжения — справа налево; линейные операторы GF(2) позволяют проверить срезы без повторного чтения целого IDAT для каждой границы. [Документированная операция объединения CRC](https://zlib.net/manual.html#Checksum) независимо проверяется по `zlib.crc32(A+B)` на случайных и граничных данных.

CRC из исходника не меняется. После её совпадения существующий PNG-читатель проверяет полный zlib/Adler-поток, точное число строк, фильтры 0–4, палитру, порядок вспомогательных блоков и полное декодирование. В одной логической PNG-цепочке допускается один такой разрыв внутри IDAT; остальные IDAT должны сохраниться целыми. Различные допустимые изображения отклоняются как неоднозначные. Равные байты из разных физических мест не доказывают первоначальное размещение файла.

Виртуальный IDAT хранит собственные физические части и конец последней части. Хвост PNG читается после этого физического конца, а не по `начало + логическая длина`. Выход состоит только из непересекающихся диапазонов исходного образа, с полным покрытием результата. Перекодирования, дополнения нулями и изготовления CRC нет.

## Ограничения и продолжение

- До 4096 опор; до `max_states × 32` пар заголовок/опора и `max_states × 8` проверок срезов.
- До 128 МиБ фактически хешируемых CRC-байтов и 64 МиБ сохранённых логических IDAT-кандидатов; не более 128 кандидатов.
- Вспомогательный хвост: окно 65536 байт, до 4096 возможных заголовков, до 128 блоков цепочки.
- Сохраняются общие пределы чтения, декодирования, времени, размера файла и числа PNG-состояний. Заголовки IDAT больше 2 МиБ, произвольные несекторные разрывы и несколько повреждённых IDAT этим резервным путём не охватываются.

При исчерпании бюджета поиск помечается неполным, кандидат до перебора альтернатив не публикуется, курсор текущего PNG не продвигается. Отмена проверяется через существующую границу чтения и сообщения прогресса. Возобновление использует проверенный индекс и повторяет незавершённый PNG, не сериализуя временные CRC-массивы. Новый модуль включён в отпечаток выполняемого кода; контрольная точка другой версии обработки не принимается.

Статус результата остаётся `png_crc_zlib_reassembled_candidate`: структура согласована, но авторство, первоначальные байты и удаление не удостоверены. Карта воспроизводит найденные байты, а не доказывает исходное расположение.

## Текущие доказательства

Независимый генератор не импортирует код восстановления: Pillow создаёт изображение и DEFLATE, отдельный PNG-писатель распределяет поток по блокам, отдельный обратный фильтр сверяет исходные пиксели. Эталонная карта не передаётся поиску.

Основной корпус содержит 26 собственных случаев: 17 точных разрозненных оригиналов, целый контроль, шесть вариантов порчи/утраты/недопустимого контекста и два случая с различными допустимыми изображениями. Последние девять не публикуют собранный файл. Сохранившиеся границы включают 512 байт, 4/32/128 КиБ и 1280 КиБ; проверены несколько IDAT, палитра, вспомогательные блоки, разрыв самой CRC, обратное размещение и одинаковые копии продолжения.

На первоначальных 25 случаях опубликованный обработчик `v2026.11.02-telegram-media-cache` восстановил один из 17 разрозненных оригиналов, новые **исходники** — 17 из 17. Добавленный 26-й контроль сохраняет начало A, разорванный IDAT изображения A и целый IDAT другого изображения B без второго PNG-заголовка. Ранний выбор B был ошибкой: теперь проверяются обе возможности и выдаётся `png_ambiguous`. Успешное декодирование первой находки не доказывает уникальность.

В отдельном исходном прогоне PNG 1575294 байт с разрывом на 1310720 байт восстановлен побайтно примерно за 0,31 с с 11092064 учтёнными проверенными байтами. Это диагностическое время одного малого образа; оно не сравнивается с временем запуска старого исполняемого файла.

Новые 10 тестов с параметризованными случаями прошли на исходниках. Независимый обзор проверил 13 других PNG: девять точных восстановлений и четыре корректных отказа, 1107 CRC-контролей и 45 физических разложений, отмену, продолжение и отклонение изменённого кода или результата.

Новый собранный helper прошёл `PngIdatGapPortableTests`: 34 фактических вызова обработчика и публичного конвейера, все 26 случаев, 17 точных оригиналов, физические карты, галерея, отмена и продолжение. Два неоднозначных случая не выдаются за единственный оригинал. Полная offline-приёмка комплекта завершилась успешно: 59 основных наборов, четыре набора Telegram и один USB-конвейера; Python отсутствовал в PATH, исходники и исполняемые файлы проверены по хешам. Это собственные обычные образы, а не испытания настоящих устройств или новое сравнение с платными программами.

```powershell
python tests/PngIdatGapRecoveryTests.py
python tests/build_png_idat_gap_fixtures.py .build/png-idat-fixtures
```

Каталог назначения генератора должен отсутствовать. Для проверки готовой программы нужен отдельный фактический portable-прогон с новым helper.
