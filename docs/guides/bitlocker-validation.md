# Приёмка полного BitLocker-тома

13 ноября 2026 года принят один полный независимый BitLocker-том: публичный
учебный образ [GTekSD/BitLocker-CTF](https://github.com/GTekSD/BitLocker-CTF/tree/db6caa8f7ddd6d659c2fd33417c64ee6b6c26ee1).
Исходный адаптер и фактический portable helper восстановили все **69 206 016 байт**;
каждый байт и конец файла совпали с независимым `libbde 20260916`.
Проверки CRC и AES-CCM сохранены. Продуктовый код для этой приёмки не менялся.

Это AES-128-CBC без diffuser (`0x8002`), BitLocker v2, парольный protector,
512-байтные секторы, три исправные копии метаданных, без EOW.
Другие шифры, protector, изменяющиеся состояния шифрования и реальные устройства
этим результатом не подтверждаются.

## Образ и независимый оракул

Автор публикует пять RAR-частей общим размером 14 210 362 байта и
[готовый тестовый пароль в решении](https://github.com/GTekSD/BitLocker-CTF/blob/db6caa8f7ddd6d659c2fd33417c64ee6b6c26ee1/answer/you-looser/u-need-to/learn/a-lot/kiddo/go/see-this/answer.md).
Пароль не подбирался. Репозиторий образца имеет MIT License.
Образ и расшифрованные данные остаются в локальном `.build`; в Git входят только
тест, описание и [манифест происхождения](../../tests/fixtures/bitlocker-full-volume/GTekSD.json).

Оракул — официальная Windows cp312 x64 wheel
[`libbde-python 20260916`](https://pypi.org/project/libbde-python/20260916/)
из независимого проекта [libyal/libbde](https://github.com/libyal/libbde).
Её SHA256 из PyPI: `26056eb2e3c5a2a26fa2a335ab54d43ac27e839b0a5b453a9dc6da6f35aa19cb`.
Тест сверяет wheel и реально загруженный модуль, расшифровывает полный раздел
через `pybde`, затем потоково сравнивает оба полных результата.
Указанный digest plaintext измерен при этой проверке; автор CTF его не публиковал.

VHDX преобразован через `dissect.hypervisor 3.21` без монтирования: родителя и
активного журнала нет. Получены все объявленные байты виртуального диска и
раздела, без дописывания хвоста. Эта операция общая для двух реализаций;
расшифрование BitLocker у `libbde` и продукта независимое.

## Что проверено

- Полный размер результата равен объявленному и доступному размеру тома;
  результат `complete/OK`, без предупреждения об усечении
- Все 69 206 016 байт обоих результатов и EOF совпали с полным оракулом;
  SHA256 файла, результата и sidecar согласованы
- Исходный адаптер и portable helper отклонили неверный пароль как `AUTH_FAILED`;
  helper завершился с кодом 2, каталог результата и plaintext не созданы
- SHA256 контейнера, диска, раздела, оракула и helper совпали до и после проверки
- В протоколе, отчёте и потоках helper нет переданного пароля;
  секрет поступал helper только через stdin
- Проверен фактический helper выпуска `v2026.11.13-images-postbox-lvm`, source
  `9195d41`, SHA256 `21873c7f71816f4f8e8992ea397b398cbfd35030b8490d899b2bb0df55832d4e`;
  в PATH дочернего процесса Python отсутствовал

Проверка исполняла helper через его реальный stdin-протокол. Окно приложения,
Windows native BitLocker, физические диски и устройства не использовались.
Сеть во время исполнения физически не блокировалась.
BitLocker не аутентифицирует все секторы данных: точное совпадение с оракулом
доказывает этот образец, а не целостность произвольного повреждённого тома.

Ранее отклонённый `dfVFS bdetogo.raw` остаётся невалидным для строгого читателя:
его CRC не исправлялись. Этот новый результат не меняет прежние failed receipts.

## Повторение

Нужны существующее окружение разработки с зависимостями recovery helper,
дополнительные `dissect.hypervisor==3.21`, `defusedxml==0.7.1` и указанная
официальная wheel `libbde-python==20260916`. Устанавливать их можно в отдельный
локальный каталог через `pip --target`; зависимости runtime менять не нужно.

1. Скачать пять `findme_encrypted.partNN.bin` по raw-ссылкам указанного commit,
   сверить размеры и SHA256 с манифестом
2. Создать отдельные копии с расширением `.rar`; проверить список архива:
   только `secret_data.vhdx`, размер 71 303 168 байт
3. Распаковать только этот файл в отдельный каталог, проверив CRC всех частей,
   затем сверить SHA256 контейнера; не монтировать
4. Запустить `tests/BitLockerFullVolumeTests.py` с параметрами `--container`,
   `--oracle-module-dir`, `--oracle-wheel`, `--helper` и новым `--output`
5. Передать один JSON-объект `{"password":"значение из опубликованного решения"}`
   через stdin. Не передавать секрет аргументом и не сохранять его в журнале

Тест не скачивает данные сам. Отсутствующие входы — ошибка, а не пропущенная
успешная приёмка. Он сохраняет `receipt.json`, полные файлы сравнения и очищенные
NDJSON-потоки в новом `--output`; существующий каталог повторно не использует.
Для другой версии Python/ОС необходима отдельно проверенная официальная wheel
и осознанное обновление её pin, без отключения проверки.

Принятая локальная квитанция этого прогона:
`.build/bitlocker-full-volume-20261113/acceptance-03/receipt.json` в worktree
`remaining-offline-20261113`. Этот тест требует внешнего образца и не подменяет
обычные обязательные проверки сборки.
