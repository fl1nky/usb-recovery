# Сборка и проверка Recovery

Эта инструкция относится к разработке под Windows x64. Для обычного запуска используй [готовый выпуск](https://github.com/fl1nky/usb-recovery/releases/latest): Python и компилятор пользователю не нужны

## Что находится в Git и в выпуске

| Место | Содержимое |
|---|---|
| Репозиторий | C#-исходники, Python-обработчик, сценарии сборки, тестовые исходники и документация |
| Переносимый выпуск | Готовая программа, PhotoRec/TestDisk, ADB, замороженный Python helper, лицензии, исходники и офлайн-зависимости пересборки helper |
| Локальная рабочая папка | `.build`, сгенерированные тестовые образы и результаты, которые не входят в Git |

Исходники сами по себе не содержат готовый Python runtime и наборы бинарных зависимостей. Сначала распакуй весь переносимый выпуск

## Подготовить рабочую папку

Склонируй репозиторий и перейди в него

```powershell
git clone https://github.com/fl1nky/usb-recovery.git
Set-Location usb-recovery
```

В архиве выпуска есть папка `Готовая программа`. Скопируй из неё три каталога в соответствующие места клона:

- `tools` → `tools` — готовые обработчики, PhotoRec/TestDisk и ADB
- `helpers/recovery_engine/wheels` → `helpers/recovery_engine/wheels` — закреплённые Python-колёса
- `vendor/iphone-backup-decrypt` → `vendor/iphone-backup-decrypt` — исходники закреплённой зависимости

В `tools/recovery-helper/rebuild` также остаётся самостоятельный офлайн-комплект пересборки helper

Копировать поверх текущего Python-кода из Git не нужно. Колёса проверяются по `SHA256.json`, зависимости закреплены в `requirements-wheel-lock.txt`. Эти локальные файлы остаются вне истории Git

## Собрать Windows-интерфейс

В PowerShell из корня проекта выполни

```powershell
.\build.ps1
```

Сценарий использует компилятор .NET Framework из Windows и создаёт `USB-Recovery.exe` в корне. Для полного запуска рядом должен оставаться каталог `tools`

## Пересобрать Python helper

Нужен Windows x64 Python 3.12. В качестве проверенной версии использовался Python 3.12.14. Установи его для разработки, затем передай путь к интерпретатору сценарию

```powershell
$taskPython = (Get-Command python.exe -ErrorAction Stop).Source
& $taskPython -c 'import sys; assert sys.version_info[:2] == (3, 12), sys.version'
.\build-engine.ps1 -Python312 $taskPython
```

Сценарий создаёт `.build/engine-env`, устанавливает закреплённые локальные колёса без обращения к индексу пакетов, запускает Python-тесты и собирает `tools/recovery-helper` через PyInstaller. В комплект обработчика включаются лицензии, исходники и офлайн-зависимости следующей пересборки

## Подготовить переносимую папку

После сборки основного EXE и helper выполни

```powershell
.\package.ps1
```

Сценарий создаёт или обновляет `Готовая программа`, копирует зависимости и формирует `package-sha256.json`. Он требует готовые PhotoRec/TestDisk и ADB в `tools`, а также предусмотренные им тестовые образцы. Эти зависимости берутся из переносимого выпуска, а не загружаются произвольными версиями

Если упаковщик сообщает об отсутствующем тестовом файле, восстанови соответствующую папку `tests` из того же выпуска. Не подменяй проверяемые образцы личными файлами

## Как проверять изменения

`build-engine.ps1` запускает поддерживаемые Python-регрессии до упаковки. C#-тесты находятся в `tests/*.cs`; каждый набор содержит собственную точку входа и компилируется с основной сборкой

Для приёмки готовой папки предусмотрены:

- `tests/QualityOfflineTests.ps1` — методы восстановления, сессии, каталог и интерфейс собственных сигнатур
- `tests/TelegramOfflineTests.ps1` — экспорты, дампы, Android DB/WAL и миниатюры через готовый helper
- `tests/UsbOfflineTests.ps1` — встроенные PhotoRec/TestDisk на тестовых образах
- `tests/verify_upgrade_package.py` — сверка уже полученных журналов с конкретными файлами поставки

Офлайн-приёмка создаёт временные правила Windows Firewall и требует соответствующих прав. Часть C#-наборов требует заранее созданные искусственные образы в `.build`; чистый клон без подготовки не считается полной тестовой средой. Не запускай проверки на исходной флешке или личном профиле вместо тестовых данных

Проверяющий Python-сценарий не запускает восстановление заново и не превращает старый зелёный журнал в подтверждение новой сборки. После изменения EXE, helper, зависимостей или тестов нужные проверки выполняются повторно
