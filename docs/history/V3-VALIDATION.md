## Достоверность и сохранение данных

Копирование создаёт `snapshot/` и `acquisition.json`; записывает исходный путь/идентификатор, размер, метаданные и SHA256. Обрыв или отмена не превращают `.partial` в завершённый файл. При продолжении проверяются завершённая копия и доступные метаданные источника. Входные файлы синтетических проверок сравнивались по SHA256 до и после работы.

SQL выполняется только над проверенными рабочими SQLite-копиями, а SQL-команды старого Signal не исполняются как произвольный SQL. MAC защищённых WhatsApp/Signal проверяется до публикации подтверждённого результата; испорченный источник получает ошибку или замечание. Повреждённое вложение современного Signal может оставить достоверные сообщения с частичным статусом, но само вложение исключается.

Сообщение хранит приложение, снимок, доступные ID чата/автора/сообщения, текст, дату, исходный файл и номер записи. Фрагменты имеют отдельную категорию и неизвестные связи. Идентичность фотографий — SHA256 содержимого; совпадающий текст сообщений без подтверждённых ID не объединяется. Номер frame современного Signal сохраняется только как ссылка на запись.

В опубликованном архиве проверены отсутствие переданных секретов, безопасное отображение HTML и ограничение внешних запросов через CSP. HTML-экспорт не исполняется. Архив намеренно содержит открытый текст и расшифрованные вложения. Секреты тестовых fixtures в исходниках стенда не являются сохранёнными пользовательскими секретами.

## Что не проверено на настоящих устройствах

Не выполнены аппаратные сценарии Android/iPhone: несколько подключённых телефонов, блокировка, отсутствие доверия, неподтверждённый ADB, реальный отказ доступа, разрыв кабеля и возобновление после такого разрыва. Ошибки потока/отмены/доступа покрыты искусственными провайдерами; это подтверждает обработку ошибок, но не совместимость конкретного телефона и драйвера.

Не выполнены восстановление с флешки пользователя и сравнение с коммерческой программой на одном реальном носителе. Облачный вход, root/jailbreak, обход блокировки, облачные Signal Secure Backups, создание новых backups и восстановление обратно в мессенджеры отсутствуют по границам версии 3.

## Воспроизведение проверок разработчиком

Исходники стендов и результаты находятся в `tests/`. Для основного worker используется локальное окружение `.build/engine-env` с Python 3.12; для тестов Signal требуется независимая библиотека `cryptography`. Пользователю программы эти окружения не нужны.

```powershell
& .\tests\verify-v3.ps1
# Дополнительные проверки разработчиком с уже установленными зависимостями:
& .\tests\verify-v3.ps1 -Python312 .\.build\engine-env\Scripts\python.exe
```

Стенды C# компилируются из одноимённых `.cs` с явным `/main` и актуальными исходниками продукта; приложенные результаты относятся к выполненным сборкам. В готовой папке распространяются исходники стендов, а не требование устанавливать компилятор на компьютере пользователя. Хеши окончательных EXE/DLL/PYD фиксирует `package-sha256.json` при упаковке; исторические хеши версии 2 не используются как хеш версии 3.
