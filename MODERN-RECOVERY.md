# Интерфейс и новые способы восстановления — 29.10.2026

Готовый комплект находится в папке «Готовая программа». Переносить нужно папку целиком: `USB-Recovery.exe` вместе с `tools`. Python, Rust, сеть и платная подписка для запуска не требуются.

## Новый интерфейс

- Тёмная боковая навигация, светлая рабочая область, синий акцент, отдельные блоки источника/назначения и карточки с пояснениями. Градиентов и анимаций нет.
- По умолчанию открывается раздел флешек. Android, iPhone и Telegram доступны через прежние разделы.
- Этапы: источник → образ и поиск → проверка файлов. PhotoRec работает без отдельного консольного окна; состояние остаётся в приложении, подробности — в журнале.
- Пять профилей: стандартный, быстрый по записям, фотографии, после форматирования, максимальный. Любая ручная правка включает «Свои настройки»; выбранные параметры сохраняются в `search-options.json`.
- 19 галочек, пять вкладок, прокрутка на небольшом экране. Режим пропуска ошибок чтения и текстовый поиск всегда включаются отдельно.
- Общий список показывает уникальные файлы, количество копий, источник и состояние. Экспорт по SHA256 и исходные результаты сохранены.

Изображения настоящего интерфейса на искусственных данных: `tests/Modern-main.png`, `Modern-extra.png`, `Modern-results.png`, `Modern-compact.png`. Это визуальная проверка, не найденные пользовательские файлы.

## Два дополнительных метода

### Потерянные каталоги FAT

Вкладка «Доп. поиск» → «Потерянные каталоги FAT». Полезно, когда ссылка на каталог исчезла из корня/родителя, но структура каталога и записи внутри ещё лежат на носителе. Поиск проверяет `.`/`..`, номер собственного кластера, допустимые записи и известную текущую занятость. Затем обычный парсер пытается извлечь содержимое.

Поддерживаются FAT12/16/32; exFAT не входит в этот метод. Известные занятые кластеры не копируются как чужие удалённые файлы. Если обычное перечисление текущих владельцев не удалось завершить, дополнительный проход пропускается. Ограничения: до 10 000 обнаруженных каталогов плюс общие лимиты метаданных. Родительские пути не выдумываются; кандидаты сохраняются в `orphan-*`, помечаются «Потерянный каталог». Факт удаления файла и целостность не устанавливаются по одной такой записи.

Также исправлено чтение сохранившихся обычных записей внутри удалённого каталога FAT: удаление родителя не обязано помечать удалёнными все записи дочерних файлов.

### Текстовые остатки в образе

Вкладка «Доп. поиск» → «Текстовые остатки по словам». Указать от 1 до 8 слов, не более 256 символов. Все слова должны находиться в одном фрагменте, регистр не важен; это буквальный поиск, без Regex. Для Telegram отдельный прежний Regex-поиск сохранён.

Поиск работает по всему обычному образу с перекрывающимися блоками, проверяет строки UTF-8 и Latin/Cyrillic UTF-16 LE/BE. Может помочь найти часть утраченного TXT, открытого текста SQLite/документа или другого доступного участка. Сжатые DOCX/PDF-потоки и шифрованные данные этот метод сам не распаковывает и не расшифровывает.

Результат — до 5000 отдельных TXT в `text-fragments`, не более 8192 символов в одном обнаруженном участке. `text-search.json` хранит путь образа, исходное смещение в байтах, длину и кодировку. TXT записывается в UTF-8. В общем списке выводится «Фрагмент, не документ». Границы исходного документа, принадлежность приложению, автор, дата и факт удаления неизвестны. Могут встречаться соседние посторонние символы и ложные совпадения; проверяй контекст.

Образ открывается только для чтения. SHA256 исходника проверяется прежним конвейером; контрольная сумма находится рядом с `usb.dd` либо в папке результатов внешнего образа. Файлы из разных проходов объединяются по содержимому, сохраняя все ссылки на оригиналы и отчёт смещений.

## Дополнительные направления, которые пока не встроены

| Возможность | Что может дать | Что потребуется |
|---|---|---|
| Свои сигнатуры PhotoRec для редких форматов | Начало неизвестного типа файла по известному образцу | Проверенные сигнатуры и контроль размера/окончания; заголовка самого по себе недостаточно |
| Возобновляемый съём GNU ddrescue и чтение его карты | Меньше повторного чтения исправных участков повреждённой флешки | Отдельный Linux-инструмент, карта от того же носителя и точная проверка идентичности; текущая собственная карта JSON с ним несовместима |
| Извлечение сохранившихся скрытых/обычных файлов из потерянного раздела с исходными именами | Иногда «пропавшие» файлы существуют, но недоступен каталог или раздел | Отдельный режим копирования существующих файлов с сохранением атрибутов; не следует называть его undelete |
| Метаданные ext2 и дополнительные файловые системы | Расширить поддержку флешек, которые использовались в Linux | Новые адаптеры и независимые образы; для ext3/ext4 обещать undelete по аналогии с ext2 нельзя |

Эти направления не представлены как работающие галочки. Уже включённые TestDisk/PhotoRec, поиск резервных записей, альтернативная FAT, JPEG-фрагменты, контейнеры и изображения по любому байту сохранены.

Windows читает доступные через контроллер логические секторы USB. Прямое чтение NAND-чипа, аппаратный ремонт и возврат перезаписанных/стёртых контроллером байтов в программу не входят. Все проверки ниже выполнены на искусственных файлах/потоках; реальный USB пользователя отсутствовал.

Тесты профилей проверяют реальные поля параметров; новые методы проверяются не только построением UI. Unicode/UTF-16-фрагменты сверяются с байтами искусственного образа по точному смещению. GUI запускается с отключённым обнаружением устройств. Не подтверждалось восстановление на реальной повреждённой флешке.

Проверка готовой папки отдельно фиксируется в `tests/UsbOffline-validation.json`, `tests/UsbOfflineTests.result.txt`, `tests/ModernPackage-validation.json`; окончательные суммы исполняемых частей — `package-sha256.json`. Старые отчёты сохраняются как история этапов.

Основная инструкция выбора режимов: USB-DEEP-GUIDE.md. Первичные источники дополнительных направлений: [свои сигнатуры PhotoRec](https://www.cgsecurity.org/wiki/Add_your_own_extension_to_PhotoRec), [GNU ddrescue и карты](https://www.gnu.org/software/ddrescue/manual/ddrescue_manual.html), [TestDisk undelete](https://www.cgsecurity.org/testdisk_doc/undelete.html).

## Окончательный комплект

Готовая папка повторно проверена после исправления компоновки вкладок: 16 сквозных USB-проверок (реальные включённые PhotoRec/TestDisk и новый текстовый проход), 17 проверок переносимого Telegram. Python отсутствовал в PATH, исходящие соединения обработчиков блокировались временными правилами; правила удалены. Контрольные суммы всех 159 исполняемых частей совпали с package-sha256.json, копии исходников соответствуют рабочим. Машинное свидетельство: tests/ModernPackage-validation.json. Это синтетическая локальная проверка, не опыт восстановления настоящего USB пользователя.
